# 开发规范

## 补充必要上下文

- 当仓库存在 `context.md` 或 `context-map.md` 时，先读取定位模块边界，再按需阅读对应 crate 文档。
- 当仓库存在 `docs/adr/` 时，先列出文件名并按需读取。
- 列出 `rules/` 下的 `ast-grep` 规则文件名并按需读取。
- 执行 `mise tasks` 查看已有命令；仅当需要修改规则时再读取配置细节，以避免浪费上下文。

## 编码规范

- 严禁编写代码注释，应当通过命名与类型表达意图，以避免注释过期污染上下文；仅当同时满足不归属 ADR 且存在隐藏约束、微妙不变量、外部已知缺陷或反直觉行为时，允许添加简短注释。配置文件允许注释。
- 当发生异常或审查到代码越界时，优先新增 lint 规则而非补充自然语言规则，必要时两者配合，避免引入临时规则。

## 命令规范

- 当需要引入新命令时，必须先接入 `mise` 或 `hk` 作为统一入口，仅当命令专属于本地或一次性使用时可独立执行；接入的命令应当保持静默执行，仅当发生异常时输出日志，以避免污染上下文。
- 当本次修改需要提交代码时，避免提前手动执行 `mise` 检查命令，交由 Git Hook 自动执行。
- 当提交 PR 后等待校验时，优先执行 `gh pr merge --auto --squash --delete-branch && (gh pr checks --watch -i 30 --fail-fast > /dev/null 2>&1 || gh pr checks)`，以抑制轮询日志刷屏。
